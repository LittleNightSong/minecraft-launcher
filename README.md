# Minecraft Launcher

一个用 Python 写的 Minecraft 启动器，目前提供命令行界面。

## 目前功能

- 安装 1.7+ 的原版实例，以及 Fabric、NeoForge 加载器实例
- 启动 1.7+ 的游戏实例（支持在线、离线、LittleSkin 登录，可指定内存与快速进入存档 / 服务器）
- 管理多个储存库（记录、切换、查看已安装版本数）
- 备份实例数据（可分别选择存档、模组、配置、资源包、光影包，默认只备份配置）
- 删除实例
- 服务器的记录、Ping 与一键进入
- 扫描并管理本机的 Java 入口点
- 查询玩家 UUID / 名称

## 安装与运行

需要 Python 3.14。

```bash
uv run .\cli.py --help
```

`cli.py --help` 会列出所有命令，任意命令加上 `--help` 都能看到详细参数。
大多数涉及实例的命令都支持 `-r/--repo` 指定储存库名称或路径，未指定时使用配置中选中的储存库。

## 实例元数据说明

启动器使用自己的数据结构（`VersionMeta`）和文件格式（实例目录下的 `*.mpk`）存放实例元数据，
而原版启动器以及 PCL 等第三方启动器只会写出 Mojang 格式的 `*.json`。
因此从其它启动器迁移过来的实例可能“缺少描述文件”，需要生成一次 `.mpk` 才能被识别。

## 命令概览

| 命令 | 说明 |
| --- | --- |
| `install` | 安装版本（可选加载器与加载器版本） |
| `launch` | 启动指定名称的实例 |
| `list` | 列出可用的 Minecraft 版本或本地实例 |
| `show` | 显示单个实例的详细信息 |
| `remove` | 删除实例 |
| `backup` | 备份实例数据 |
| `fix-instance-metadata` | 为缺少 `.mpk` 的实例生成描述文件，并自动推断 |
| `server` | 服务器的记录、Ping 与进入 |
| `java` | 扫描 / 列出本机的 Java |
| `repository` | 管理储存库 |
| `mojang` | 查询玩家 UUID / 名称 |

## 致谢

以下工作由 **DeepSeek** 完成：

- **`list` 命令的修复**：修正位置参数 `version` 无法生效、`--type all` 无输出乃至崩溃、
  在线模式下 `--type` 不参与去重、本地实例读取版本号的优先级错误（导致整合包被误判为
  愚人节版本）等问题，并统一了版本号解析与筛选逻辑。
- **`fix-instance-metadata` 命令**（新增）：把第三方启动器写出的 `.json` 转换为启动器自己的
  `.mpk`，并自动推断原版版本号、加载器与加载器版本号、客户端主文件。推断完全基于本地信息
  （`clientVersion`、`id`、以及与本储存库中已知版本的发布时间比对），默认不联网；
  无法可靠推断时直接跳过，不会写入可能错误的版本信息。
- **`show` 命令**（新增）：展示实例的类型、原版版本号、加载器与加载器版本号、占用空间、
  存档 / 资源包 / 光影包 / 模组 / 数据包数量，以及从客户端 jar 的 `version.json` 中读取的
  资源包与数据包格式版本。
